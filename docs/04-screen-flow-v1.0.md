인터랙티브 명리·운세 사이트
화면 흐름 설계서 v1.0
(MVP 범위: 연애운·직업운)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

문서 목적

본 문서는 사용자가 사이트에 진입해서 결과를 확인하기까지 거치는 화면을 순서대로 정의한다.

각 화면마다 다음을 명세한다.

화면 목적
표시 요소
사용자 액션
다음 화면으로의 전이 조건
필요한 입출력 데이터

본 문서는 디자인 시안이 아니라 개발 지시서용 구조 명세다. 실제 비주얼(색상·폰트·캐릭터 이미지)은 별도 디자인 단계에서 정한다.


---

01. 전체 화면 흐름 요약

S1. 인트로 화면
    ↓
S2. 카테고리 선택 화면
    ↓
S3. 정보 입력 화면
    ↓
S4. 계산 처리(로딩) 화면
    ↓
S5. 결과 화면
    ↓ (선택)
S6. 부가 기능 잠금 화면 (PDF/공유, 광고 시청 후 해제)


---

02. S1. 인트로 화면

목적: 사이트 진입 시 첫인상. 캐릭터를 통해 사이트의 톤을 각인시킨다.

표시 요소:
- 캐릭터 등장 애니메이션/일러스트
- 짧은 환영 멘트 (예: "오늘 당신의 운세가 궁금한가요?")
- [시작하기] 버튼 1개

사용자 액션:
- [시작하기] 탭

전이 조건:
- [시작하기] 탭 → S2로 이동

입출력 데이터: 없음 (정적 화면)

비고: [확정] 재방문자 처리는 11번 미결사항 ③ 참조 — 로컬 저장소(localStorage)에 확인 플래그가 있으면 S1을 건너뛰고 바로 S2로 이동한다.


---

03. S2. 카테고리 선택 화면

목적: 사용자가 보고 싶은 운세 종류를 선택.

표시 요소:
- 카테고리 버튼 목록 (MVP: 💕 연애운, 💼 직업운 두 개만 노출. 나머지 4개는 화면에 아예 노출하지 않는다 — 11번 미결사항 ② 확정 참조)
- 카테고리별 짧은 설명 1줄

사용자 액션:
- 카테고리 버튼 중 하나 탭

전이 조건:
- 카테고리 선택 → 해당 카테고리 값을 세션에 저장하고 S3로 이동

입출력 데이터:
- 출력: selected_category (love | career)


---

04. S3. 정보 입력 화면

목적: 사주 계산에 필요한 정보 수집.

표시 요소:
- 카테고리에 맞는 인트로 대사 1줄 (템플릿 매핑 규칙서 06번 참조)
- 입력 폼:
  - 이름 (텍스트, 선택 입력 가능 — 비워도 진행 가능, 비우면 "당신"으로 대체)
  - 생년월일 (날짜 선택)
  - 양력/음력 선택 (라디오)
  - 음력 선택 시: 윤달 여부 (라디오, 음력 선택 시에만 노출)
  - 출생시간 (시:분 선택, "시간 모름" 옵션 포함)
  - 성별 (라디오)
- [결과 보기] 버튼

사용자 액션:
- 각 필드 입력
- [결과 보기] 탭

전이 조건:
- 필수 필드(생년월일, 양력/음력, 성별) 입력 완료 시에만 버튼 활성화
- 출생시간 "모름" 선택 시: 시주 계산 제외하고 년/월/일주만으로 계산 (계산 규칙서 쪽에 이 경우의 처리 규칙이 있는지 확인 필요 — 없다면 규칙서에 추가해야 함)
- [결과 보기] 탭 → 입력값 검증 통과 시 S4로 이동

입출력 데이터:
- 입력: name(optional), birth_date, calendar_type(solar|lunar), is_leap_month, birth_time(optional), gender
- 출력: 위 값을 계산 엔진 입력 스키마로 포장하여 S4로 전달

주의: 입력 화면 자체는 "정보를 입력하면 결과가 바로 나온다"는 방침에 따라 캐릭터 연출 없이 폼 위주로 간결하게 구성한다.


---

05. S4. 계산 처리(로딩) 화면

목적: 계산 엔진이 원국을 계산하고 템플릿을 매칭하는 짧은 처리 시간을 자연스럽게 연결.

표시 요소:
- 짧은 로딩 애니메이션(캐릭터가 무언가를 살펴보는 느낌의 짧은 모션)
- 로딩 문구 1개 (예: "사주를 살펴보고 있어요…")

사용자 액션: 없음 (자동 진행)

전이 조건:
- 계산 완료 시 자동으로 S5 이동
- [확정] 최소 노출 시간 0.8초 고정(11번 미결사항 ④ 참조). 실제 계산은 이보다 빠르게 끝나도 화면은 0.8초 유지 후 전환한다.

내부 처리(화면에는 안 보이지만 이 단계에서 실행):
1. 입력값 → 사주 계산 엔진 (원국 산출)
2. 원국 → 특징값 추출 (십신 강세 유형 + 신강/신약)
3. 특징값 → pattern ID 매핑
4. selected_category + pattern ID + 생년월일시 해시 → 템플릿 버전 선택
5. 템플릿의 {이름} 등 변수 치환

입출력 데이터:
- 입력: S3에서 전달받은 값
- 출력: result_text(치환 완료된 최종 텍스트), pattern_id(로깅/분석용)


---

06. S5. 결과 화면

목적: 최종 결과를 보여주는 핵심 화면. 체류시간과 광고 노출이 발생하는 지점.

표시 요소:
- 카테고리명 + (있다면) 이름 삽입된 헤드라인 (예: "{이름}님의 연애운")
- 매칭된 템플릿 결과 텍스트
- (출생시간 "모름" 선택 시에만) "출생시간을 몰라 시주는 제외하고 계산했어요" 안내 문구
- 디스플레이 광고 영역 (애드센스)
- 하단 버튼: [다른 운세도 보기] [PDF로 저장] [공유하기]

사용자 액션:
- [다른 운세도 보기] 탭 → S2로 복귀 (카테고리만 재선택, 이미 입력한 생년월일 등은 세션에 유지해서 재입력 안 시킴)
- [PDF로 저장] 또는 [공유하기] 탭 → S6으로 이동

전이 조건:
- 사용자 선택에 따라 S2 또는 S6으로 분기

입출력 데이터:
- 입력: S4의 result_text
- 출력: 없음 (단, 사용자가 다른 카테고리 선택 시 이전에 입력한 생년월일 정보는 재사용)


---

07. S6. 부가 기능 잠금 화면

목적: PDF 다운로드/공유 기능을 리워드 광고 시청과 연결.

표시 요소:
- 안내 문구 (예: "광고를 보면 PDF로 저장할 수 있어요")
- [광고 보기] 버튼

사용자 액션:
- [광고 보기] 탭 → 리워드 광고 재생

전이 조건:
- 광고 시청 완료(스킵 없이 끝까지) → 기능 잠금 해제 → PDF 생성/공유 시트 노출
- 광고 중도 이탈 → 잠금 유지, S5로 복귀

입출력 데이터:
- 입력: result_text (PDF 생성용)
- 출력: PDF 파일 또는 공유용 링크/이미지

주의(애드센스 정책): 광고 시청 완료 시 반드시 약속한 기능(PDF/공유)을 제공해야 하며, 시청 전에 "무엇을 주는지" 명확히 고지해야 한다.


---

08. 세션 데이터 유지 범위

한 방문 세션 동안 아래 값은 재입력 없이 유지한다.

name
birth_date
calendar_type
is_leap_month
birth_time
gender

즉 연애운을 보고 나서 직업운도 보고 싶으면 S2(카테고리 선택)부터 다시 시작하되, S3(정보 입력)는 건너뛰고 바로 S4로 갈 수 있다. 이는 "운세 콘텐츠를 하나씩 본다"는 기획 의도와도 맞고, 재방문 시 이탈을 줄이는 효과도 있다.

예외: 사용자가 명시적으로 "다른 사람 사주 보기" 같은 옵션을 선택하면 세션 값을 초기화한다. (MVP에는 이 옵션 자체가 없으므로 향후 확장 시 고려)


---

09. 화면별 광고 배치 원칙

S5(결과 화면): 디스플레이 광고 1개 배치. 결과 텍스트를 가리지 않는 위치.
S6(잠금 화면): 리워드형 광고 1개.
S1~S4: 광고 배치 없음 (탐색·입력 흐름을 방해하지 않기 위함)


---

10. 확장 시 변경 지점

카테고리를 추가할 때 변경이 필요한 화면은 S2(선택지 추가)뿐이다. S1, S3~S6은 구조 변경 없이 그대로 재사용된다.


---

11. 확정이 필요한 미결 사항

다음 항목은 이 문서만으로 결정할 수 없어, 별도 결정이 필요하다.

① [해결됨] 출생시간 "모름" 선택 시 계산 규칙 — 계산 규칙서 v2.0 4번: 시주를 확정하지 않는다(AI 임의 추정 금지). 특징값 추출 시 시주를 제외한 년/월/일주만 사용하도록 템플릿 매핑 규칙서 v1.1 01-1번에 반영 완료. S3 화면에서 "시간 모름" 선택 시, S5 결과 화면에 "출생시간을 몰라 시주는 제외하고 계산했다"는 안내 문구를 추가로 노출해야 한다(S5 표시 요소에 반영 필요).
② [확정] 준비 중인 나머지 4개 카테고리(재회운·재물운·결혼운·종합운) — S2 화면에서 숨긴다. 비활성 버튼으로 노출하면 "왜 안 되지"라는 이탈 요인이 되고, MVP는 "적은 카테고리를 제대로 보여준다"는 방향과도 맞지 않는다. 카테고리 추가 시 S2 목록에 새 버튼만 추가하면 되므로 숨겨둬도 확장 비용은 없다.

③ [확정] 재방문자 S1(인트로) 스킵 여부 — 로컬 저장소(localStorage 등, 서버 저장 아님)에 "인트로 확인함" 플래그를 남기고, 같은 브라우저 재방문 시 S1을 건너뛰고 바로 S2로 이동한다. 최초 방문 인상은 지키면서 재방문 마찰은 줄이는 절충안.

④ [확정] S4 로딩 화면 최소 노출 시간 — 0.8초로 고정한다. 실제 계산은 그보다 빠르게 끝나지만, 너무 빨리 화면이 바뀌면 "캐릭터가 살펴보는" 연출 의도가 사라지므로 최소 시간을 의도적으로 둔다.
