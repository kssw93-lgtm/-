06. 양력/음력 처리

사용자가 양력을 선택한 경우:

입력 양력 날짜 ↓ 표준 날짜시간 변환 ↓ 사주 계산

음력을 선택한 경우:

음력 날짜 ↓ 윤달 여부 확인 ↓ 검증된 음양력 데이터 조회 ↓ 양력 날짜 변환 ↓ 사주 계산

음력 날짜를 임의의 산술 공식으로 변환하지 않는다.

07. 윤달

음력의 윤달은 일반 월과 동일하게 취급하지 않는다.

예: 윤4월 은 일반적인 4월 과 구분하여 저장한다.

음력 데이터: lunar_year, lunar_month, lunar_day, is_leap_month 을 모두 보존한다.

09. 대한민국 표준시

기본 계산에서는 대한민국 표준시를 사용한다.

timezone = Asia/Seoul

표준시와 진태양시를 동시에 적용하지 않는다.


---

10. 진태양시

서비스 초기 기본값: true_solar_time = false

즉, 대한민국 표준시를 그대로 사용한다.

향후 진태양시 방식을 지원할 경우: 표준시 ↓ 출생지역 경도 ↓ 시간 보정 ↓ 시주 계산 을 별도 계산 프로파일로 만든다.

기존 결과를 변경하지 않도록 설정값을 버전 관리한다.


---

11. 년주 기준

년주는 단순한 양력 연도만으로 결정하지 않는다.

입춘을 년주 변경 기준으로 사용한다.

입춘 이전 → 이전 년주
입춘 이후 → 해당 연도 년주

단순히 1월 1일 = 년주 변경 으로 처리하지 않는다.


---

12. 입춘 경계

입춘의 정확한 시각을 절기 데이터에서 조회한다.

예: 입춘 2026-02-04 05:XX:XX

출생 2026-02-04 04:59 → 이전 년주
출생 2026-02-04 05:01 → 새로운 년주

정확한 판단은 저장된 절입 시각을 사용한다.


---

13. 년주 계산

년주는 60갑자 순환을 사용한다.

해당 연도의 천간·지지를 계산하고, 입춘 이전 → 이전 연도 간지 / 입춘 이후 → 해당 연도 간지 를 적용한다.

년주 계산 결과는: year_stem, year_branch, year_pillar 로 저장한다.


---

15. 월지 경계

각 월지는 해당 절입 시각부터 다음 절입 직전까지 적용한다.

예: 입춘 시각 ↓ 寅月 시작 / 경칩 시각 ↓ 卯月 시작

따라서 달력의 1일 기준으로 월지를 변경하지 않는다.

16. 월간 계산

월간은 오호둔월법을 사용한다.

寅月의 시작 천간:

甲·己年 → 丙寅
乙·庚年 → 戊寅
丙·辛年 → 庚寅
丁·壬年 → 壬寅
戊·癸年 → 甲寅

이후 월지가 하나 증가할 때마다 천간도 하나 증가한다.

천간 순서: 甲 乙 丙 丁 戊 己 庚 辛 壬 癸


---

17. 월주 생성

예를 들어 寅月이 丙寅 이면 이후: 丁卯 戊辰 己巳 庚午 辛未 壬申 癸酉 甲戌 乙亥 丙子 丁丑 순으로 진행한다.

18. 일주 계산

일주는 반드시 검증된 역법 데이터 또는 검증된 60갑자 일진 계산 방식을 사용한다.

기본 구조: Gregorian Date ↓ 일진 계산 ↓ 60갑자 index ↓ day_pillar

일주 계산에서 가장 중요한 것은 기준일(reference date)이다.

기준일과 해당 날짜의 간지 관계를 고정해야 한다.


---

19. 일주 기준일 [v2.1 확정]

일주 엔진에는 다음 설정값이 존재한다.

REFERENCE_DATE = 2024-01-01
REFERENCE_DAY_PILLAR = 甲子 (갑자, index 0)

교차검증점(독립 계산 대조): 2026-07-02 = 丁丑(정축, index 13). REFERENCE_DATE로부터 913일 경과 → 913 mod 60 = 13 → 정축. 두 날짜가 서로 일치함을 확인했다.

주의: 이 기준값은 독립 계산기 1곳의 검증 결과를 근거로 잠정 확정한 것이다. 규칙서 20번(일주 검증)에 따라, 실제 서비스 Production 반영 전에는 KASI 데이터 또는 추가 독립 만세력 자료와 한 번 더 교차검증해야 한다. 이 값이 KASI 데이터와 어긋나면 REFERENCE_DAY_PILLAR을 KASI 기준으로 교체하고 버전을 올린다(day_pillar_dataset_version 갱신).

임의의 인터넷 사주 사이트 값을 검증 없이 기준일로 사용하지 않는다는 원칙은 유지하되, 개발 착수를 위해 위 값으로 우선 진행한다.


---

20. 일주 검증

일주는 다음과 같이 교차 검증한다.

자체 계산 + 공식/검증 역법 데이터 + 독립적인 만세력 계산

결과가 일치해야 Production에 반영한다.


---

21. 날짜 경계

기본 서비스 프로파일에서는 날짜 경계를 00:00 으로 관리한다.

단, 자시를 날짜 변경으로 처리하는 별도 명리학 방식이 존재하므로 해당 부분은 계산 프로파일에서 명시적으로 관리한다.

AI가 상황에 따라 변경하지 않는다.


---

22. 자시 처리 [v2.1 확정]

기본 시지: 子時 = 23:00 ~ 00:59 (23번 시지표 그대로 유지, 변경 없음)

DAY_BOUNDARY_MODE = midnight 로 확정한다.

의미: 날짜(일진)가 바뀌는 기준은 00:00이다. 23:00~23:59에 태어난 사람도 그날 날짜의 일진을 그대로 사용하고(다음날로 넘기지 않음), 00:00~00:59에 태어난 사람은 그날(새 날짜)의 일진을 사용한다.

주의: 이것은 시지(어느 시각이 子時인가) 판정과는 별개다. 23:30 출생과 00:30 출생은 둘 다 시지가 子(자)이지만, 일주(day_pillar)는 서로 다른 날짜 값을 가진다 — 23:30은 그날 날짜의 일주, 00:30은 다음날 날짜의 일주. 즉 시천간(24번, 오자둔시법 계산)에는 "그 시각이 속한 일주의 일간"을 사용해야 하므로, 23:00~23:59 출생자의 시천간 계산에는 그날(자정 이전) 날짜의 일간을 쓴다.

DAY_BOUNDARY_MODE = zi_start(23시부터 날짜 변경) 방식은 채택하지 않는다. 향후 학파별 옵션을 지원할 경우 계산 프로파일(69번)에 별도 모드로 추가할 수 있으나, 서비스 공식 기준은 midnight 하나로 고정하고 전체 사용자에게 동일하게 적용한다.

31. 십신 계산

십신은 일간을 기준으로 한다.

관계: 비견 겁재 식신 상관 정재 편재 정관 편관 정인 편인

계산 과정: 일간 + 상대 천간의 오행 + 음양 관계 ↓ 십신

십신을 AI가 판단하지 않는다. 고정된 매핑 규칙을 사용한다.


---

32. 지장간 십신

지지 자체를 하나의 십신으로 처리하지 않는다.

지장간 각각을 일간과 비교한다.

예: 일간 甲, 寅(甲 丙 戊) — 각 지장간에 대해 독립적으로 십신을 계산한다.

45. 신강·신약

신강·신약은 오행 단순 개수로 판단하지 않는다.

계산 엔진은 최소한 다음 원자료를 제공한다.

월령, 일간, 통근, 천간 오행, 지지 오행, 지장간, 생조 관계, 극설 관계

실제 신강·신약 판정은 명리 해석 엔진의 규칙을 따른다.

46. 격국

격국 역시 계산 엔진에서 임의로 판단하지 않는다.

계산 엔진은 월령, 월지, 월지 본기, 월간, 투간, 일간 등의 원자료를 제공한다.

격국 판정은 해석 엔진에서 수행한다.


---

47. 조후

조후 판단을 위해 계절, 월령, 오행 분포, 일간 을 계산 데이터로 전달한다.

실제 조후 판단은 명리 해석 규칙에서 수행한다.


---

48. 용신·희신·기신

계산 엔진에서 임의로 결정하지 않는다.

구조: 계산 엔진 ↓ 원국 데이터 ↓ 명리 해석 엔진 ↓ 용신 희신 기신 으로 분리한다.


---

49. 대운 방향

기본 채택 규칙:

년간 음양	성별	대운
양	남성	순행
음	남성	역행
양	여성	역행
음	여성	순행

즉: 양남 순 / 음남 역 / 양녀 역 / 음녀 순 으로 고정한다.


---

50. 대운 계산

대운은 월주를 기준으로 순행 또는 역행한다.

출생시각 ↓ 기준 절기 ↓ 절기까지 시간 간격 ↓ 대운 시작 나이 ↓ 월주 기준 순행/역행 ↓ 10년 단위 대운

기준 절기 선택 규칙 [v2.1 확정]: 반드시 월주 경계에 쓰이는 12절(14번 참조, 24절기 전체가 아님)만 사용한다.
- 순행(49번 표에 따라 forward인 경우): 생일시부터 다음 절입시각까지의 시간 간격을 사용한다.
- 역행(backward인 경우): 생일시부터 직전 절입시각까지의 시간 간격을 사용한다.

대운 시작 나이는 단순히 만 나이로 계산하지 않는다.


---

51. 대운 기산 [v2.1 확정]

기본 환산 규칙: 3일 = 1년(정확히), 즉 4320분(3일×24시간×60분) = 1년

계산 절차:
1. 시간차_분 = |생일시 − 기준 절입시각| (분 단위, 82번 표준시 이력 정규화 이후의 시각 기준)
2. 대운수_정밀 = 시간차_분 ÷ 4320  (소수점 유지, 절대 중간에 반올림/절삭하지 않음)
3. 대운 시작 정확한 날짜(52번 "시작 날짜" 필드) = 생년월일시 + 대운수_정밀 년을 실제 캘린더에 더한 날짜. 이 값은 소수 그대로 사용한다.
4. 대운 시작 "나이" 표기값(사람이 보는 화면용 정수)은 대운수_정밀을 소수 첫째자리에서 반올림해서 만든다. 반올림 규칙: 0.5는 올림(예: 3.5 → 4).

이렇게 나이 표기용(반올림된 정수)과 실제 날짜 계산용(정밀 소수값)을 분리해서, 반올림으로 인한 오차가 날짜 계산에 누적되지 않게 한다.

시간 단위는 가능한 한 원래 시간 간격을 유지하여 계산한다는 원칙(정밀 소수값 유지)은 위 절차로 충족한다.


---

52. 대운 출력

각 대운은 최소: 대운 번호, 대운 간지, 시작 나이, 종료 나이, 시작 날짜, 종료 날짜 를 생성한다.

53. 세운

세운은 해당 연도의 60갑자를 계산한다.

연도 ↓ 60갑자 ↓ 세운

세운 자체는 계산 데이터로 제공하고, 원국+대운+세운의 의미는 해석 엔진에서 판단한다.


---

54. 월운

월운은 일반적인 양력 월이 아니라 절기 월령을 기준으로 계산한다.

연간 + 절기 월지 ↓ 월운 으로 계산한다.


---

55. 운세별 분석 데이터

계산 엔진은 운세별 결론을 직접 생성하지 않는다.

예: 연애운, 재회운, 재물운, 직업운, 결혼운, 종합운 은 명리 해석 엔진에서 계산된 원자료를 사용한다.


---

56. 연애운

연애운 분석에 사용할 수 있는 원자료: 일간, 재성, 관성, 배우자궁, 일지, 합충, 대운, 세운, 월운

계산 엔진은 위 데이터를 제공한다.

"올해 무조건 연애한다" 등의 문장을 계산 엔진이 생성하지 않는다.


---

57. 재회운

재회운 분석에 필요한 원자료: 배우자궁, 합충, 재성/관성, 대운, 세운, 월운

실제 재회 가능성 판단은 해석 엔진에서 수행한다.


---

58. 재물운

원자료: 재성, 식상, 일간 강약 관련 데이터, 대운, 세운, 월운, 합충

단순히 "재성이 많다 = 부자" 로 판단하지 않는다.


---

59. 직업운

원자료: 관성, 인성, 식상, 재성, 일간, 월령, 대운, 세운 을 사용한다.


---

60. 궁합

궁합 계산은 두 명의 독립적인 사주 데이터를 계산한 후 비교한다.

A 사주 + B 사주 ↓ 오행 관계 ↓ 천간 관계 ↓ 지지 관계 ↓ 배우자궁 ↓ 대운/세운 ↓ 궁합 해석

한 사람의 사주를 기준으로 다른 사람을 추정하지 않는다.

62. 계산 결과 수정 금지

계산 엔진에서 생성된 year_pillar, month_pillar, day_pillar, hour_pillar 은 이후 AI가 수정할 수 없다.

예를 들어 AI가 "이 사주는 설명상 辰시가 더 맞는 것 같아요." 라고 판단하여 시주를 바꾸는 것은 금지한다.

63. 경계값 테스트

반드시 테스트: 입춘 직전/직후, 절기 직전/직후, 22:59/23:00/23:59/00:00/00:59/01:00, 음력, 윤달, 시간 미상


---

64. 독립 검증

계산 엔진 개발 완료 후 최소한 자체 계산 엔진 + 독립적인 역법 계산 + 검증된 만세력 자료 와 비교한다.

특히 년주 월주 일주 시주 가 모두 일치해야 한다.


---

65. 테스트 데이터

테스트 데이터는 개발자가 임의로 만든 정답을 사용하지 않는다.

다음 기준으로 구축한다: 공식 역법 자료 + 검증된 계산 + 독립 구현

테스트 유형: 일반 날짜, 입춘 경계, 절기 경계, 자시 경계, 음력, 윤달, 대운, 해외 시간대


---

66. 테스트 자동화

계산 엔진은 자동 테스트가 가능해야 한다.

입력 ↓ 계산 ↓ expected result ↓ 일치 여부

결과: PASS / FAIL 으로 출력한다.


---

67. 계산 규칙 버전

본 문서는: SAJU_CALCULATION_RULES v2.0 이다.

계산 방식 변경 시: v2.1, v2.2, v3.0 등으로 버전을 올린다.


---

68. 데이터 버전 분리

계산 규칙 버전과 데이터 버전은 별도로 관리한다.

예: calculation_rules = 2.0 / solar_terms = 1.0 / lunar_calendar = 1.0 / day_pillars = 1.0

이렇게 해야 과거 결과를 재현할 수 있다.


---

69. 계산 프로파일

계산 방식에 학파적 차이가 존재하는 경우 코드에 흩어놓지 않고 하나의 프로파일로 관리한다.

예: CALCULATION_PROFILE_KR_V2

포함: timezone, year_boundary, month_boundary, day_boundary, zi_hour_rule, true_solar_time, luck_direction, luck_start_rule

서비스 출시 시 하나의 프로파일을 공식 기준으로 지정한다.


---

70. AI가 사용할 수 없는 정보

AI는 웹 검색이나 자체 지식만으로 사주팔자를 다시 계산해서는 안 된다.

올바른 구조: 사용자 입력 ↓ 계산 엔진 ↓ 확정된 사주 데이터 ↓ AI

잘못된 구조: 사용자 입력 ↓ AI가 사주 계산 ↓ AI가 해석


---

71. 계산 엔진 우선순위

사주 결과를 생성할 때 다음 우선순위를 지킨다.

1. 사용자 입력
2. 역법 데이터
3. 계산 규칙
4. 계산 엔진
5. 해석 엔진
6. AI 표현

AI의 일반적인 명리학 지식은 계산 결과보다 우선할 수 없다.


---

72. 개인정보 처리와 계산

기본 서비스는 가능한 한 사용자 입력 ↓ 일시적 계산 ↓ 결과 표시 ↓ 입력 데이터 폐기 구조를 우선한다.

단, 실제 서비스에서 개인정보를 수집·처리하는 경우에는 별도로 개인정보 보호법 및 관련 법률에 맞는 개인정보 처리방침과 필요한 고지·동의 여부를 검토해야 한다.

"저장하지 않는다 = 개인정보 책임이 완전히 없다"로 간주해서는 안 된다.


---

73. 계산 엔진 최종 구조

사용자 → 출생정보 → 입력 검증 → 양력/음력 변환 → 시간대 처리 → 절기 조회
→ (년주 / 월주 / 일주) → 시주 → 사주팔자
→ (오행 / 음양 / 지장간) → 십신 → 합충형파해원진 → 통근/월령
→ 공망 계산 → 대운 계산 → 세운 계산 → 월운 계산
→ 명리 해석 엔진 → 운세 콘텐츠 → AI 표현 엔진 → 캐릭터/대화/영상


---

74. 최종 핵심 원칙

① 사주 계산은 AI가 하지 않는다.
② 년주는 입춘 기준으로 계산한다.
③ 월주는 절기 기준으로 계산한다.
④ 음력은 검증된 음양력 데이터를 사용한다.
⑤ 윤달은 일반 월과 구분한다.
⑥ 일주는 검증된 일진 데이터와 교차검증한다.
⑦ 자시 경계는 하나의 계산 프로파일로 고정한다.
⑧ 시주는 오자둔시법으로 계산한다.
⑨ 오행 단순 개수만으로 신강·신약을 판단하지 않는다.
⑩ 합충형파해의 존재와 실제 해석을 분리한다.
⑪ 대운은 별도의 계산 모듈로 처리한다.
⑫ 계산 데이터와 명리 해석을 분리한다.
⑬ 계산 결과와 AI 자연어 표현을 분리한다.
⑭ 모든 핵심 계산은 테스트 데이터로 검증한다.
⑮ 계산 규칙과 역법 데이터는 각각 버전 관리한다.
⑯ 동일한 입력 + 동일한 규칙 + 동일한 데이터 = 동일한 사주 결과
